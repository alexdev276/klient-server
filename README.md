# Клиент-сервер на Qt: ЛР6 и ЛР7

Консольное приложение на Qt 6 (C++17) с четырьмя режимами работы:

| Режим      | Назначение                                              | Порт по умолчанию |
|------------|---------------------------------------------------------|-------------------|
| `server6`  | UDP-сервер чата (ЛР6)                                   | 5555              |
| `client6`  | UDP-клиент чата (ЛР6)                                   | 5555              |
| `server7`  | Сервер распределённого подбора ключа Виженера (ЛР7)     | 50050             |
| `client7`  | Клиент распределённого подбора ключа Виженера (ЛР7)     | 50050             |

## Сборка

1. Откройте `CMakeLists.txt` в Qt Creator и соберите проект.
2. Или из терминала:

```bash
cmake -S . -B build
cmake --build build
```

Требуется Qt 6 с модулями `Core` и `Network`.

## Запуск

Без аргументов программа показывает меню выбора режима. Режим можно задать и аргументом:

```bash
./klient-server server6 [порт]
./klient-server client6 [адрес] [порт] [имя]
./klient-server server7 [порт]
./klient-server client7 [адрес] [порт]
```

По умолчанию клиент подключается к серверу `192.168.8.159`, поэтому адрес можно не
указывать. Другой адрес передаётся первым аргументом.

Локально на одной машине (сервер и клиент в разных терминалах):

```bash
./klient-server server7                  # терминал 1
./klient-server client7 127.0.0.1 50050  # терминал 2
```

По сети (сервер на машине `192.168.8.159`):

```bash
./klient-server server7                  # на серверной машине
./klient-server client7                  # на клиентской машине
```

## Три машины: сервер и два клиента

На всех трёх машинах нужна одна и та же сборка и общая локальная сеть. Сервер при запуске
печатает свои адреса:

```
[ЛР7] Сервер распределенных вычислений запущен на порту 50050
Адрес для клиентов: 192.168.8.159 (en0)
```

Этот адрес указывают клиентам; он же используется по умолчанию, поэтому у клиентов адрес
можно не писать. Если сервер напечатал несколько адресов, выбирайте адрес
локальной сети (Wi-Fi/Ethernet, например `en0`), а не служебный адрес VPN.

**Машина 1 — сервер:**

```bash
./klient-server server7          # для ЛР7
./klient-server server6          # для ЛР6
```

**Машины 2 и 3 — клиенты:**

```bash
./klient-server client7 192.168.8.159 50050
./klient-server client6 192.168.8.159 5555 Ноутбук-2
```

В ЛР7 клиенты автоматически получают разные диапазоны ключей; после находки сервер печатает
ключ и прекращает выдачу заданий. В ЛР6 сервер пересылает сообщения каждого клиента всем
остальным, поэтому все три машины видят общий чат.

Если соединения нет, разрешите входящие UDP-соединения для `klient-server` в брандмауэре
(macOS: «Системные настройки» → «Сеть» → «Брандмауэр») и проверьте, что машины находятся в
одной подсети.

## ЛР6 — UDP-чат на несколько клиентов

Клиент регистрируется на сервере (`HELLO:<имя>`), сервер подтверждает регистрацию
(`WELCOME`) и пересылает каждое сообщение (`MSG:<текст>`) остальным участникам в виде
`CHAT:<имя>:<текст>`. Поэтому две и более машины видят общий чат, а не только ответ сервера.

Выход — команда `exit`; при выходе клиент отправляет `BYE`, и остальные видят сообщение об
отключении. Пустые строки не отправляются. Имя задаётся последним аргументом `client6`,
по умолчанию — «Клиент».

## ЛР7 — распределённый поиск ключа

Сервер раздаёт клиентам диапазоны ключей по 1000 значений: 1000–1999, 2000–2999, …,
9000–9999 и отдельно 10000. Клиент перебирает ключи в полученном диапазоне, расшифровывая
шифртекст, и ищет фразу `is120`.

Протокол (UDP, текстовые датаграммы):

- `HELLO` / `NEXT` — запрос задания; ответ `шифртекст|начало|конец`;
- `RETRY` — повтор последнего выданного этому клиенту задания (защита от потери датаграмм);
- `FOUND: <ключ>` — клиент нашёл ключ;
- `NO_MORE_TASKS` — задания закончились либо поиск уже завершён.

Клиент ждёт ответ 3 секунды и делает до 5 попыток, после чего завершается с сообщением об
ошибке. Найдя ключ, клиент отправляет его серверу и выходит; сервер печатает найденный ключ
и останавливает выдачу заданий.

Шифртекст и диапазон ключей заданы в `udpserver.cpp`. Чтобы заменить демонстрационные
данные, сформируйте новый шифртекст тем же алгоритмом:

```cpp
QString cipher = Vigenere::encrypt("открытый текст с фразой is120", "7351");
```

Ключ должен попадать в диапазон 1000–10000.

## Алгоритм Виженера

`vigenere.cpp` использует алфавит из методических указаний (кириллица с `Ё`, латиница,
цифры и знаки). Дубли символов в исходной строке отбрасываются. Позиция в ключе
увеличивается только на символах, входящих в алфавит, поэтому символы вне алфавита не
сбивают расшифровку. Реализованы `encrypt()` и `decrypt()`.

Файлы старой TCP-версии (`mainwindow.*`, `server.*`, `client.*`, адаптеры,
`vigenereclient/vigenereserver/vigenereworker`) оставлены в папке, но в сборку не входят.
