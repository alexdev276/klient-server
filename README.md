# Сетевые приложения «Клиент-Сервер» на Qt (ЛР 4–7)

Проект реализует клиент-серверные приложения на Qt 6 (C++) по методическим
указаниям дисциплины «Инфокоммуникационные системы и сети»:

1. **ЛР 4** — TCP-чат: обмен текстовыми сообщениями между клиентами через сервер
   (паттерн **Adapter**, классы `QTcpSocket` / `QTcpServer`).
2. **ЛР 5** — распределённые вычисления: сервер делит диапазон на подзадачи,
   раздаёт их клиентам, собирает результаты (вариант 1: площадь `sin(x)` при
   `Y > 0`; дополнительно вариант 4: корни `cos³(x)`).
3. **ЛР 6** — UDP-чат: обмен сообщениями между клиентом и сервером по протоколу
   UDP (`QUdpSocket`), регистрация клиентов и рассылка сообщений.
4. **ЛР 7** — распределённый подбор ключевой фразы шифра Виженера по UDP:
   сервер выдаёт клиентам-дешифровщикам диапазоны ключей, клиенты перебирают их
   в отдельном потоке и возвращают результат. Признак расшифровки — фраза
   `is120` в открытом тексте.

---

## Сборка

### Qt Creator
1. Откройте `CMakeLists.txt`.
2. Выберите комплект Qt 6 (модули Core, Gui, Network, Widgets, Concurrent).
3. **Сборка → Собрать проект «klient-server»**.

### Командная строка
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
```

После сборки рядом с исполняемым файлом автоматически появляются `keys.txt`
(набор ключевых фраз) и `kmzi.ini` (порты ЛР 7).

## Запуск

При запуске приложения выберите режим:

| Пункт меню | Что запускается |
|---|---|
| ЛР 4-5: TCP сервер | сервер чата и распределённых вычислений (порт 5555) |
| ЛР 4-5: TCP клиент | клиент чата/вычислений |
| ЛР 6: UDP сервер (чат) | UDP-сервер на порту 5555 |
| ЛР 6: UDP клиент (чат) | UDP-клиент, ищет сервер по IP |
| ЛР 7: сервер подбора ключа | UDP-сервер: порты 50050 (обнаружение) и 50055 (обмен) |
| ЛР 7: клиент-дешифровщик | клиент, перебирающий ключи в отдельном потоке |

Для запуска нескольких копий используйте **Run** в Qt Creator несколько раз
или запустите собранный бинарник из терминала.

---

## ЛР 6. UDP-чат

1. Запустите **ЛР 6: UDP сервер (чат)** — он занимает UDP-порт 5555.
2. Запустите одну или несколько копий **ЛР 6: UDP клиент (чат)**.
   IP сервера по умолчанию `127.0.0.1`; для работы по Wi-Fi укажите IP
   компьютера с сервером.
3. Клиент регистрируется на сервере (`HELLO`), сервер отвечает `WELCOME` и
   рассылает сообщения всем подключённым клиентам (`CHAT`).

Протокол (текстовые дейтаграммы UTF-8):
```
HELLO:<имя>          клиент → сервер: регистрация
WELCOME:<имя>        сервер → клиент: подтверждение
MSG:<текст>          клиент → сервер: сообщение
CHAT:<автор>:<текст> сервер → клиенты: рассылка
BYE                  клиент → сервер: отключение
```

## ЛР 7. Распределённый подбор ключа Виженера

### Порядок работы
1. Запустите **ЛР 7: сервер подбора ключа**.
   * Алфавит уже заполнен алфавитом из методички (повторяющиеся символы
     автоматически удаляются: в исходной строке дважды встречаются `g` и пробел).
   * Вставьте кодированную комбинацию (можно с переносами строк).
   * Проверьте файл ключевых фраз (по умолчанию `keys.txt` рядом с программой;
     можно выбрать другой кнопкой **Загрузить ключи**).
   * Нажмите **Начать поиск**.
2. Запустите одну или несколько копий **ЛР 7: клиент-дешифровщик**.
3. В клиенте нажмите **Найти сервер** (IP можно оставить пустым — тогда
   используется широковещательный запрос и `127.0.0.1`).
4. Сервер выдаёт клиенту диапазон ключей, клиент перебирает их в отдельном
   потоке. При обнаружении `is120` сервер получает ключевую фразу и рассылает
   всем клиентам команду остановки. Если диапазон закончился без результата,
   сервер выдаёт следующий.

### Конфигурация `kmzi.ini`
```ini
[network]
discoverPort=50050
exchangePort=50055

[search]
chunkSize=200
keysFile=keys.txt
```
Сервер читает эти значения при старте (файл создаётся автоматически, если его
нет). `chunkSize` — сколько ключевых фраз выдаётся за одно задание.

### Протокол ЛР 7
```
KMZI_DISCOVER:<порт>                 клиент → broadcast: поиск сервера
KMZI_SERVER:<порт обмена>            сервер → клиент: адрес найден
KMZI_CONFIRM:<порт>                  клиент → сервер: подтверждение связи
KMZI_TASK:<id>:<алфавит>:<шифр>:<от>:<до>:<ключи>   сервер → клиент
KMZI_ACK:<id>                        клиент → сервер: задание принято
KMZI_RESULT:<id>:<1|0>:<ключ>:<текст>  клиент → сервер: результат
KMZI_STOP[:<ключ>]                   сервер → клиенты: остановить перебор
KMZI_WAIT                            сервер → клиент: поиск ещё не начат
KMZI_DONE                            сервер → клиент: задания закончились
```
Алфавит, шифртекст, ключи и открытый текст передаются в Base64, поэтому
разделитель `:` не конфликтует с содержимым.

## Автотесты

Собранный бинарник поддерживает консольные проверки:

```bash
cd build
./klient-server --selftest     # шифр Виженера: encrypt/decrypt + перебор
QT_QPA_PLATFORM=offscreen ./klient-server --lab6test   # UDP-чат
QT_QPA_PLATFORM=offscreen ./klient-server --lab7test   # полный цикл ЛР 7 по UDP
```

Ожидаемый результат: `SELFTEST PASSED`, `LAB6 TEST PASSED`, `LAB7 TEST PASSED`.

## Запуск по сети (Wi-Fi)

1. Узнайте IP серверного компьютера (macOS: `Option` + клик по Wi-Fi;
   Windows: `ipconfig`).
2. В клиентских приложениях укажите этот IP:
   * ЛР 4-5 — поле «IP сервера» в окне клиента;
   * ЛР 6 — поле «IP сервера»;
   * ЛР 7 — поле «IP сервера» (иначе широковещательный поиск).
3. Убедитесь, что брандмауэр разрешает UDP 5555 (ЛР 6) и UDP 50050/50055 (ЛР 7).
